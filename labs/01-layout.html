Create and serve the project

1. Extract the downloadable teaching kit. Open the starter folder in VS Code. Confirm that index.html, styles.css, app.js and data/farms.geojson exist. Folder and filename spelling must match the HTML references.

2. Open a terminal inside starter. Start a local server using the command for your system.

Code example
# macOS or Linux
python3 -m http.server 8000

# Windows with the Python launcher
py -m http.server 8000

3. Visit http://localhost:8000 in the browser. If the command is unavailable, install Python 3 or use VS Code Live Server. Live Server supplies its own URL and port. Do not assume it uses port 8000.

4. Read the supplied index.html scaffold. Find the map, search, district, activity, results and detail ids. Match each label for attribute to its control id.

5. Compare the scaffold with the complete HTML shown below. You may type it into a new empty file for practice. Copy the complete HTML block into one index.html file.

Checkpoint

The heading and labelled controls appear. The map space remains empty because app.js does not initialise a map yet. This is the expected state at this point.

Record your evidence

Write down the local URL and show the page in the browser. Explain why opening the page through the server is preferable to double-clicking index.html when fetch will be used later.

Stop the server with Ctrl+C when finished. Keep it running during the practical work.

Complete HTML scaffold

index.html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Zanzibar Aquaculture Atlas Lab</title>
  <link rel="stylesheet"
    href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css">
  <link rel="stylesheet" href="styles.css">

    src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js"></script>
  <script defer src="app.js"></script>
</head>
<body>
  <header>
    <h1>Zanzibar Aquaculture Atlas</h1>
    <p>Surveyed farm locations - September 2026</p>
  </header>

      <label for="activity">Activity</label>
      <select id="activity"><option value="">All activities</option></select>
      <div class="actions">
        <button id="reset" type="button">Reset</button>
        <button id="fit" type="button">Fit results</button>
      </div>
      <p id="count" aria-live="polite">Loading data...</p>
      <p id="status" role="status"></p>
      <h2>Matching locations</h2>
      <div id="results"></div>

      <div id="map"></div>

</html>

Create a responsive layout

6. Replace the starter styles.css with the CSS shown below. The stylesheet creates a sidebar, a map column, readable controls and an activity legend.

7. Reload the page. Narrow the browser below 700 pixels. The sidebar should move above the map. Increase browser zoom to 200 percent and check labels, buttons and text.

Before moving on

• Inspect #map in browser developer tools and confirm it has height.

• Use Tab to move through the controls and check the visible focus outline.

• Explain why box-sizing: border-box helps inputs fit the sidebar.

• Change the header colour once, reload, and restore the supplied colour.

Mini challenge

Add a short paragraph explaining that the data is a survey snapshot. Put it in the footer without covering the map or replacing the source note.

Expected result

A two-column workspace is visible on a wide screen, and a single-column workspace on a narrow screen. Filters are readable even before they are wired to JavaScript.

Troubleshooting

If the page remains unstyled, confirm href="styles.css", check that the server is serving the starter folder, and inspect the Network panel for a 404. A style change may require a hard refresh if the browser cached an older file.
