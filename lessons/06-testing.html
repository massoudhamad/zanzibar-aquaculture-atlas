Verify the atlas before using it

A page that loads is not sufficient evidence that its map and filters are correct. Test representative actions and compare counts with source controls. Use the table below as a classroom acceptance checklist.

Test Expected evidence
Initial load 437 records, 437 mapped, 301 responses
Activity selection 407 seaweed, 18 sea cucumber, 1 crab, 11 unspecified
No-match search Zero records and an empty-state message
Combined controls Every listed record meets all active filters
Selection and reset Details change correctly; reset restores all records
Narrow viewport Controls usable and no horizontal overflow
Missing data file An error message appears instead of a false zero

Explain the limits

This export primarily represents southern Unguja. It does not establish complete Zanzibar or Pemba coverage. Coordinate-range checks identify malformed values, but they do not prove that a location lies inside the reported district. That requires an authoritative boundary layer and a spatial check.

Review access before public sharing

Remove names, contact numbers, photographs and sensitive notes from class data. Exact locations can still require controlled sharing. The downloadable teaching kit uses anonymous record codes and omits the original workbook. Before a public launch, confirm appropriate data access and source permissions.

Basemap use

Keep map attribution visible. Review the tile provider policy before a public rollout. Do not bulk-download public OpenStreetMap tiles for an offline classroom. Use an approved provider or a permitted local basemap where needed.

Extensions after the core works

Consider a records table, a satellite basemap, marker clustering, or verified administrative boundaries. Each extension needs its own data and interaction checks. Do not add totals or indicators whose meaning is unsupported by the survey.
